# 发布到插件市场

官方插件市场是一个 Git 仓库：[`AI-for-anyone/loop-now-market`](https://github.com/AI-for-anyone/loop-now-market)。Loop Now 服务端在每次打开市场页和安装时现场读取其索引文件（`main` 分支上的 `loop-now-market.json`），所以条目一旦合并，所有用户立刻可以免确认安装。

## 收录流程

1. **把插件发布为带标签的 Git 仓库。** 索引中的条目钉在具体 tag 上，绝不指向游移的分支。
2. **向市场仓库提交 PR**，在索引中加入你的条目。每个条目合并前都经过审阅：检查插件的两半内容、声明的事件、权限和安装来源。
3. **市场 CI 用本平台仓库的插件宿主校验每个条目**，清单损坏在进入用户视野之前就会失败。
4. **合并后即收录，安装不再需要确认**——审阅步骤的意义正在于此。

正因为收录意味着隐式信任，插件清单要诚实且最小化：只声明真正用到的事件和权限。

## 范例：Slack 插件

市场上第一条插件是 [`AI-for-anyone/loop-now-plugin-slack`](https://github.com/AI-for-anyone/loop-now-plugin-slack)：

- 作为独立公开仓库发布，带发布标签；
- 在市场索引中钉在 tag `v0.1.0`；
- 通过 Socket Mode 连接 Slack 工作区（不需要公网地址）；
- 代管一个外部身份，让 Agent 能反向找人；
- 应答平台投递给它的插件渠道提问。

可以把它当作打包、打标签和准备市场 PR 的参考。

## 收录之后

- 版本保持钉死：用户显式更新，进行中的任务保留启动时的文件。
- 也可以**不走市场**发布插件——Git 地址、npm 包或本地目录——这类安装永远会先询问确认。市场是信任捷径，不是唯一的分发渠道。
- 想运行私有市场，用环境变量 `LOOP_NOW_PLUGIN_MARKET_URL` 把服务端指向你自己的索引。
