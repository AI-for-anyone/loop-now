# 核心概念

Loop Now 围绕少数几个核心概念构建。本页说明它们如何配合；细节以仓库中的 [README](https://github.com/AI-for-anyone/loop-now) 与规范为准。

## 组织、项目、Agent

层级是 **Organization → Project → Agent**，另有平台级 Agent。

- **项目**把 Agent、账号、仓库、插件和共享上下文组合在一起。
- **Agent** 有自己的模型、思考等级、指令、Skills、工具权限，以及一个持久工作目录——这个目录同时也是它的上下文。
- 项目可以指定 **Manager**。Manager 是承担协调角色的普通 Agent：你把它当作对话入口，它通过项目的任务流程分派工作。

权限由人配置；Manager 只能选择已配置的 Agent，不能临时授权。

## 对话与上下文

Agent 的**常态对话**和工作目录跨轮次保留。Agent 文件夹就是它的上下文：文件夹根目录的 `AGENTS.md` 是入口，其余文件由 Agent 自己管理。

**任务**使用独立副本：任务开始时平台克隆 Agent 文件夹（macOS 上为 APFS 克隆），并固定 workflow、配置、权限与账号的版本。同一 Agent 在同一任务的各步骤中连续复用自己的任务目录与会话；任务结束后回收执行资源，保留记录、归档会话与产物。

## Inbox：排队或打断

Agent 与人通过 **Inbox** 协作：

- 给忙碌的 Agent 发消息会**排队**，按顺序排列在输入框上方。
- 任何排队项都可以**转为打断**、编辑或取消；也可以停止当前回复，让队列继续。
- Agent 可以 **sleep**——这是空闲等待，新消息可将其提前唤醒。
- Agent 需要人决定时会**提问**；你可以内联回答或在待处理列表中作答，回答即标记已读。

## 任务与流程

任务是 Agent 执行的固定 **workflow** 节点序列，支持：

- 线性、条件分支和有次数限制的审查回路（暂不支持并行汇合）；
- 重试、取消和按节点保存的成果；
- **提问**：节点暂停，直到有人回答；
- 节点对话：每个任务节点有自己与人的往来消息线程。

任务开始后，流程与已捕获的配置**冻结**；普通重试不会刷新凭证。

## 账号与权限

项目**统一保存模型与 CLI 账号**；Agent 按权限与选择规则取用。接入供应商账号是带验证的显式动作，工具集成按 Agent 授予。

个人版**没有主密钥**：凭证以明文保存在 PostgreSQL 中。请保护好数据库访问与备份，并把控制台“仅本机回环、无登录”的设计纳入考量。

插件是平台的核心扩展入口——两半模型、宿主能力和安装授权方式见[插件体系概览](/zh/plugins/)。
